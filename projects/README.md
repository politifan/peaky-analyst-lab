# Один итоговый проект
Выберите один маршрут. Не сдавайте четыре одинаковых конспекта.

1. Денежная витрина: project-orders/project-refunds, исторические prices/items; отдельно определите суммы заказа, товаров, доставки/скидки и возврата. Для оборотного капитала добавьте собственную явно синтетическую таблицу запасов и себестоимость; без неё не называйте выручку стоимостью запасов. Обязательны сверка по order_id и объяснение неизвестных.
2. Эксперимент: assignments.csv; сначала проверьте рандомизацию, назначение, экспозицию и зрелость; затем SRM, эффект, приближённый интервал, правила семьи/guardrail. Набор синтетический, причинный бизнес-эффект не заявляется.
3. Продукт: events.csv; определите вход когорты, период жизни, зрелость и хронологию воронки. Не смешивайте count событий с count пользователей. Объясните ограничения причинности.
4. Обновляемая платформа: first/late/empty/conflict; повтор, отклонение конфликта, fault injection до CURRENT, безопасный повтор, проверяемый возврат и реальная панель.

## Рубрика каждого проекта
- Определение вопроса и измерения однозначно.
- Исходники сохранены, версии и SHA256 указаны.
- Вычисление повторяется на чистом запуске; изменённый набор пересчитывается.
- Проверены ключи, границы, пустота/неизвестное, ошибочный вход и неверный выход.
- Таблица и график согласованы, единицы и фильтр подписаны.
- Вывод имеет числовую опору, ограничение и проверяемое действие.
- README позволяет повторить, при неуспехе есть понятный возврат.

Нет автоматической оценки письменного вывода или независимого серверного экзамена вашего проекта. Локальные проверки доступны ученику и не являются защитой от подмены его среды.
